# platform

Сервис калькуляторов отпуска: считает полную стоимость поездки — перелёт,
проживание, питание вне отеля, трансфер, страховку, экскурсии и визу — и ведёт
человека к бронированию по партнёрским ссылкам.

Дорожная карта разработки: [эпики, фазы и ворота](https://claude.ai/artifact/BQEFNigERaWVEktU25V7xy).
Текущий этап — **эпик E1, каркас**.

Демо-версия главной: http://adelinasha.temp.swtest.ru

Вся разработка идёт в Docker: на хост ставить Node, Postgres и Redis не нужно.

## Разворачивание с нуля

### 1. Что нужно заранее

- [Docker Desktop](https://www.docker.com/products/docker-desktop/) (Windows/macOS)
  или Docker Engine + Compose plugin (Linux);
- Git.

### 2. Клонировать и завести `.env`

```bash
git clone https://github.com/adelina04-lab/platform.git
cd platform
cp .env.example .env
```

Значения по умолчанию совпадают с `docker-compose.yml`, поэтому для первого
запуска править `.env` не нужно. Токены партнёрских программ (`TRAVELPAYOUTS_*`
и остальные) можно оставить пустыми: приложение поднимется, а сборщики цен
сообщат, какой переменной им не хватает.

### 3. Поднять контейнеры

```bash
docker compose up -d --build
```

| Сервис | Что делает | Порт на хосте |
|---|---|---|
| `app` | Next.js в режиме разработки | 3000 |
| `postgres` | база с ценами | 5432 |
| `redis` | очереди BullMQ для сборщиков цен | 6379 |

### 4. Применить миграции

```bash
docker compose exec app npm run db:migrate
```

Сайт откроется на http://localhost:3000.

### 5. Быстрый цикл разработки

Fast Refresh через бинд-монт на Windows не работает: Turbopack не получает
события файловой системы, и после правки нужен `docker compose restart app`.
Опрос (`watchOptions.pollIntervalMs`) помогает только сборке на webpack, а
Turbopack его игнорирует — документация Next прямо советует не держать
дев-сервер в Docker.

Поэтому для работы над интерфейсом держите в Docker только базу и очереди, а
дев-сервер запускайте на хосте:

```bash
docker compose up -d postgres redis
npm install          # один раз
npm run dev
```

В `.env` при этом хост базы должен быть `localhost`, а не `postgres` —
закомментированная строка для этого уже лежит в `.env.example`.

Полный `docker compose up -d` остаётся рабочим: он нужен, чтобы проверить
сборку в том же окружении, что и на проде.

## Выкладка на хостинг

Сейчас сайт лежит на shared-хостинге SpaceWeb (`adelinasha`, 77.222.40.65) и
открывается по техническому адресу http://adelinasha.temp.swtest.ru.

Что важно знать про этот хостинг:

- **SSH отключён** — оболочка аккаунта `nologin`, поэтому ни `ssh`, ни `sftp`
  не работают, остаётся только FTP на 21 порту;
- **Node на хостинге нет**, значит дев-сервер и продакшн-сервер Next там не
  поднять.

Поэтому выкладка идёт статическим экспортом. Это работает, пока главная
считается на клиенте: демо-движок расчёта целиком в браузере, запросов к базе
и к партнёрским API страница ещё не делает.

```bash
STATIC_EXPORT=1 npm run build --workspace=@platform/web
SW_FTP_PASS='пароль от панели' ./deploy/upload.sh
```

Первая команда кладёт готовый сайт в `apps/web/out`, вторая заливает его в
`public_html` вместе с `deploy/htaccess` (он превращается в `.htaccess`:
страница 404, сжатие и вечный кеш для `_next/static`). Пароль передаётся
только переменной окружения и никуда не записывается.

`STATIC_EXPORT=1` включается только для этой сборки — `npm run dev` и Docker
работают как обычно.

### Когда статики перестанет хватать

Как только появятся серверные части — API сборщиков цен (E3, E4), страницы
направлений из базы (E6), редиректы партнёрских ссылок с метками (E9) —
shared-хостинг придётся сменить на VPS с Docker: там уже нужен работающий
Node и Postgres. Ориентир — фаза с воротами перед E6.

## Форма обратной связи

Форма отправляет сообщение на `POST /form.php` — маленький обработчик на PHP
(на хостинге PHP 7.1 и рабочий `mail()`, Node там нет). Данные нигде на сервере
не сохраняются, только уходят письмом: чем меньше персональных данных лежит на
диске, тем меньше требований к сайту по 152-ФЗ.

Чтобы форма заработала:

```bash
cp deploy/form-config.sample.php deploy/form-config.php
# вписать почту получателя, затем обычная выкладка
```

`deploy/form-config.php` не хранится в репозитории — в нём личная почта.
Без него обработчик честно отвечает `not-configured`, а форма предлагает
позвонить.

Отправлять письма лучше с ящика на собственном домене: письма с чужого адреса
почтовые службы часто не пропускают.

## Что нужно, чтобы размещать сайт законно

Сайт — российский, с формой сбора данных и партнёрскими ссылками, ведёт
самозанятая. Отсюда список, и он не формальность: за большинство пунктов с
2025 года штрафуют отдельно.

**Персональные данные (152-ФЗ)**

1. Подать уведомление в Роскомнадзор о намерении обрабатывать персональные
   данные — **до** начала обработки, то есть до того, как форма заработает.
   Самозанятые от этого не освобождены.
2. Опубликовать политику обработки — сделано, `/politika/`. Три места в ней
   помечены как ЗАПОЛНИТЬ: ФИО, ИНН и почта оператора.
3. Согласие отдельной галочкой, не отмеченной заранее — сделано.
4. Держать данные на серверах в России — SpaceWeb подходит.
5. Подключить HTTPS. Без него форма собирает данные по открытому каналу.

**Реклама (38-ФЗ)**

6. Партнёрские ссылки — реклама: нужна пометка «Реклама», данные рекламодателя
   и токен `erid` из ОРД, отчёт в ЕРИР.
7. С 1 апреля 2025 действуют обязательные отчисления 3 % с дохода от
   распространения интернет-рекламы; самозанятых это тоже касается.

**Налоги (422-ФЗ)**

8. Проверить оферту каждой партнёрской программы: НПД не применяется к доходу
   по агентскому договору и договору поручения или комиссии. Договор на
   оказание рекламных услуг — применяется. Если программа работает только по
   агентской схеме, под неё нужно ИП.

**Мелочи, без которых тоже нельзя**

9. Свой домен вместо технического адреса хостинга.
10. Уведомление о cookie и упоминание аналитики в политике — сделано.

## Структура

```
apps/
  web/            Сайт: калькулятор и SEO-страницы направлений
packages/
  core/           Движок расчёта — чистый TypeScript, без React и без базы
  db/             Prisma: схема цен и клиент
docker/
  app.Dockerfile  Образ приложения: dev, builder и runner
```

**Главное архитектурное правило:** вся математика расчёта живёт в
`packages/core` и ничего не знает о вебе. Сайт, будущий Telegram-бот,
встраиваемый виджет и мобильное приложение — тонкие клиенты одного движка.
Логика расчёта не дублируется ни при каких обстоятельствах.

Деньги везде хранятся и считаются в копейках (`valueMinor`), никогда во float.

Таблица `price_points` пополняется, а не перезаписывается: каждое наблюдение
цены ложится новой строкой с датой сбора. Через год это даёт историю цен,
которую невозможно получить задним числом.

## Команды

Все команды запускаются внутри контейнера: `docker compose exec app <команда>`.

| Команда | Что делает |
|---|---|
| `npm run dev` | дев-сервер (запускается сам при `docker compose up`) |
| `npm run build` | продакшн-сборка всех пакетов |
| `npm run typecheck` | проверка типов во всех пакетах |
| `npm run lint` | ESLint |
| `npm run test` | тесты движка расчёта |
| `npm run db:migrate` | создать и применить миграцию |
| `npm run db:generate` | перегенерировать клиент Prisma после правки схемы |
| `npm run db:studio` | Prisma Studio для просмотра данных |

## Стек

Next.js 16 (App Router, Turbopack), React 19, TypeScript, Tailwind 4,
PostgreSQL 17 + Prisma 7, Redis + BullMQ, npm workspaces + Turborepo.

Документация Next лежит в самом пакете — `node_modules/next/dist/docs/`.
Она соответствует установленной версии, и читать нужно именно её: в 16-й версии
многое изменилось по сравнению с тем, что помнят языковые модели и старые
статьи. То же касается Prisma 7: адрес базы теперь задаётся в
`packages/db/prisma.config.ts`, а не в `schema.prisma`.
